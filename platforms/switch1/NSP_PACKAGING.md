# Native Relay NRO and NSP packaging status

## Source restriction

The Switch application code under `source/` is a direct, independent C++ port of this project's own Relay UI/audio behavior and a **read-only native implementation** of Relay's own `/config.json` PBS service probe. No Akira, alternative Chiaki frontend or other Remote Play implementation is included. An unused research checkout was removed after the user clarified this restriction. The original Android files are unchanged; see the 64-file source checksum manifest.

## NRO (real devkitPro homebrew executable)

`relay-switch1.nro` is a valid NRO with native AArch64 code, original bundled Relay UI/audio assets and a title icon. `build-switch1.ps1` generates it using installed devkitPro. It now includes a read-only PS5 PBS service probe at Relay's configured LAN endpoint (the user's current native Switch prototype uses `192.0.2.10:9999`). This probe does not obtain input ownership, inject an ELF or modify any PS5 capture profile. The video decoder, controller streaming, remote-play pairing and audio-stream playback remain incomplete, so the NRO is **not a finished Remote Play client**.

## Development ExeFS PFS0 `.nsp` (NOT installable)

`relay-switch1-exefs-dev.nsp` is reproducibly generated by:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\platforms\switch1\package-exefs-dev.ps1
```

This uses devkitPro's `elf2nso`, `npdmtool` and `build_pfs0` to produce a PFS0 container with exactly `main` and `main.npdm`. The source is Relay's own `relay-switch1.elf`, not a foreign homebrew launcher. The build passes `verify_nsp_dev.py` PFS0-entry and payload checks.

**A development ExeFS PFS0 container is not a Nintendo installable application NSP.** It contains no title NCAs or control/RomFS title contents. It cannot be installed or launched as a normal standalone title by Eden or the HOME menu. It remains available only as an ExeFS packaging diagnostic.

## NCA-based application title NSP (packaging verified)

The independently implemented native Relay ELF is converted to a program NSO and packed with a native application NPDM, Relay NACP/control icon, original-derived RomFS and CNMT into an application title with ID `0100abcd23450000`. The local `cargo-nx`-wrapped hacBrewPack consumes an existing local keyset for NCA packaging; neither the keyset nor any private console material is copied or printed. No foreign Remote Play app or SD-card forwarder has been integrated.

From the repository root, first build the NRO with `build-switch1.ps1`, then:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\platforms\switch1\package-nca-title.ps1 -SkipNativeBuild
```

The packager verifies the staged NSP with `hactool --verify` **before** copying it to `nca-title-output/0100abcd23450000.nsp`. On November 23, 2026, the verified output contained three NCAs (program, control, content meta), with `Program OK`, `Control OK` and two content-meta records. The latest built artifact is 28,835,544 bytes and its SHA-256 is `c6f6846fe4b77b9dc416543221d5668a957d6315fc2e3aa4b32809120c09df22`. This proves package structure/content checks, **not runtime launch or correct playback**.

## Unfinished work

The independently implemented native app still needs end-to-end PS5 session validation, stream decode/frame timing, remote controller ownership/input and streamed audio verification; complete PSN/registration and Android-equivalent settings/quick-menu states; image/frame parity against the Android baseline; and hardware performance tests. Original menu OGG and PCM recordings are bundled and played through SDL2_mixer calls, with runtime diagnostics for failed opening/loading, but actual Switch/Eden menu audio output has not been confirmed. Source-file hashes and verified NCAs do **not** establish pixel-, animation- or audio-output parity.
