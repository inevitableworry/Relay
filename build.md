# Relay build variants

**Mandatory cross-platform rules:** Before any Relay change, read
[`RELAY_BUILD_PARITY_MASTER.md`](RELAY_BUILD_PARITY_MASTER.md). Android is the
canonical PS Portal interface and feature specification; user-requested
changes must be reviewed and implemented across **all** platform ports, or
recorded as blocked/unsupported with evidence. After **every change**, update
the master build inventory and change log, run
`python tools/check_relay_ui_parity.py`, compare real Android/target
screenshots using `python tools/compare_relay_ui_frames.py`, and separately
verify menu cues versus PS5 streamed audio. A successful build is not proof
of visual identity, game audio, input or stream functionality.

Relay has one shared Android remote-play codebase and **ten** separately installable build flavors. Changes to streaming, PS Portal-style navigation and shared settings apply to each flavor unless the change lives under a flavor-specific `src/<flavor>` directory. Local artifact naming and selected-target cleanup follow `docs/RELAY_ARTIFACT_POLICY.md`.

Output APKs are `android/app/build/outputs/apk/<flavor>/debug/app-<flavor>-debug.apk`. The TV, Shield, and Google TV flavors have separate 1280×720 banners derived from the same original Relay icon at `docs/branding/relay-icon-original.png`. Different app IDs prevent one build from overwriting another; console registrations and settings are separate per installation. The TV variants advertise Leanback and do not require touchscreen input. Shield, Google TV and Retroid package both ARM architectures; the generic Android TV and Razer Edge flavors are ARM64.

Android SDK, NDK `28.2.13676358`, host Python 3.11, Java 17, and protoc are needed. The build script makes a temporary `P:` subst alias pointing to this source tree because the native OpenSSL build cannot cope with spaces in `H:\Samsung Android`. Run `powershell -ExecutionPolicy Bypass -File .\build-android.ps1 -All -RunTests` to assemble and test all **ten** flavors at once. Use `-RunTests` to execute JVM tests before assembling. `-InstallSerial <adb-serial>` can install a selected single variant directly. Do not combine platform switches `-Tv`, `-Shield`, `-GoogleTv`, `-Bravia8II`, `-Retroid`, `-RazerEdge`, `-AynThor`, `-DualScreen`, `-MetaQuest` or `-All`.

For locally organized artifacts across platforms, run `powershell -ExecutionPolicy Bypass -File .\scripts\collect-relay-builds.ps1 -UseHardlinks`. The index at `releases/organized/artifact-index.json` records each staged artifact, SHA-256 and original location. The experimental 3DS XL/New 3DS XL uses native `platforms/3ds/build-3ds.ps1` to generate 3DSX, CIA and CCI, not APKs. These are development builds, not tested Remote Play releases.

**Release quality:** These are locally signed/debug development builds, not production release builds. Successfully compiling ARM libraries does not prove performance, decoding, controller mappings, audio, or long sessions on every Shield revision. Validate those features on target hardware.

## Translation dependency

The PlayTranslate upstream reference repository is checked out at `research/playtranslate-upstream` (`https://github.com/dominostars/playtranslate`, GPL-3.0, verified upstream revision `343c74f`). Do not vendor its entire app or screen-capture service into Relay. Relay translates the already-decoded game `SurfaceView` directly, avoiding screen-recording permissions and excluding Relay's own menus and other apps. Both streaming modes use the same session-scoped translation component. On-device ML Kit language models may need a Wi-Fi download on first use; enabling translation does not turn on system-wide capture.

### Enabling session-only automatic translation

Open **Settings → Game Translation** and turn on **Automatically Translate Game Text**. Choose **Translate To** to select the preferred output language, initially the phone/TV locale where supported, otherwise English. Relay detects text with on-device Latin, Japanese, Chinese, Korean and Devanagari OCR, identifies the source language with ML Kit, and translates only when it differs from the output language. The same preference is used for Traditional Remote Play and Remote Play JB. A quick-menu toggle is available in either streaming mode. **Off is the default.** Translation starts only after a stream connects, and stops on disconnect, backgrounding, or shutdown; it never scans the settings/launcher screen or other apps.

Current limitation: automatic OCR scans a downscaled copy of the whole decoded game image every ~3.4 seconds; script/language identification can fail for short, fast-moving, or stylized game fonts. Manual legacy subtitle mode retains its bottom-40% crop. Translation models require a Wi-Fi download before use and the first translated caption may be delayed. No MediaProjection, accessibility service, third-party app, or cloud translation permission is required. Live streaming and recognition need testing on real hardware; successful JVM/Gradle builds do not verify captions visually.

More details: `docs/RELAY_TV_VARIANTS.md`.

**Standalone Japanese translation test:** Settings → Game Translation → Japanese Translation Test now displays a bundled 1280×720 Japanese game-style image and runs the same Japanese ML Kit OCR adapter and offline translation engine without a connected PS5. Results are overlaid on the sample picture. Details and expected Japanese/English phrases are in `docs/JAPANESE_TRANSLATION_TEST.md`. This is a static OCR/model smoke test, not a validation of real-time PS5 streaming.

The standalone Japanese test succeeded on the Samsung Galaxy Tab S11 Ultra over wireless ADB on November 23, 2026; OCR read the four Japanese passages and returned an English overlay. Evidence: `docs/device-results/relay-japanese-translation-success-tablet.png`.

**Nintendo Switch V1 native UI/audio port (INCOMPLETE):** `platforms/switch1/relay-switch1.nro` now compiles a native devkitA64/libnx + SDL2 UI renderer, with untouched original Relay OGG menu cues, PCM menu music, Inter font, and nav vector paths rasterized from source. Backdrop particles, rotation, intro/fade and input are independently ported from Android animation constants, but **frame-identical visuals and audio playback are not yet verified**, and PS5 pairing/streaming/video/audio/controller backend is **not integrated**. No alternate streaming code ports are used; the previously cloned Akira research tree was removed. The Switch-native app includes an independently written read-only probe of Relay's own PBS `/config.json` endpoint, but H.264 decoding, controller ownership/input and streamed audio are unfinished. `ui_audio_animation_lock.json` protects 64 original Relay files. Build: `powershell -ExecutionPolicy Bypass -File .\platforms\switch1\build-switch1.ps1`. On the user's Samsung tablet, Eden Nightly was explicitly granted the NRO test folder but failed to open the NRO SAF file (`Error mmap'ing file`) and a direct launch returned `No game found in arguments or intent`. Therefore **Eden runtime test failed**, not passed. See `platforms/switch1/README.md`, `platforms/switch1/NSP_PACKAGING.md`, and `platforms/switch1/EDEN_TEST.md` for evidence. `relay-switch1-exefs-dev.nsp` (6.15 MB) was generated through devkitPro, but is only an ExeFS PFS0 development container, not an installable signed title NSP. Eden's actual **Manage Eden data > Install game content > Import** attempt on the Samsung Tab S11 Ultra displayed **Error installing file(s) to NAND** (one installation error). Screenshot and log: `docs/device-results/relay-nsp-eden-install-failed.png`, `docs/device-results/eden-nsp-install-log.txt`. Neither package is a completed or successfully emulated Remote Play release.

**PlayTranslate parity status:** The latest Android builds have added capture-region presets, source-positioned translated captions, an optional speech reader, controller hotkey and an opt-in local game-dialogue history. Their source code is shared by Mobile, Android TV, Shield and Google TV. This is **not full PlayTranslate feature parity**: PaddleOCR/MangaOCR, Yomitan/dictionary, Anki export, alternative offline/online model engines, furigana/Pinyin, custom rectangle crop editing, dual-screen and document/camera workflows are still outstanding. See `docs/PLAYTRANSLATE_PARITY_TRACKER.md` for the exact implemented/partial/missing checklist. Live translation remains unverified while the PS5 native capture recovery block is unresolved.
**Expanded PlayTranslate parity pass:** A new OCR engine adapter and custom game-video crop editor are in the Android source tree, alongside adjustable OCR frequency, caption styling, a local user-imported dictionary/reading screen, user-initiated AnkiDroid Basic-note export and a custom OpenAI-compatible HTTPS translation engine with encrypted key storage. The default remains local ML Kit and the cloud engine must be explicitly configured and enabled. Native PaddleOCR/MangaOCR, bundled/full Yomitan, rich Anki media cards, alternate local translation models, split-screen/camera/document readers and full 26-language OCR coverage are **not** complete. See `docs/PLAYTRANSLATE_PARITY_TRACKER.md` for exact boundaries; do not advertise complete PlayTranslate feature parity. None of these changes bypasses the PS5's native capture recovery block.

## Other platforms (separate ports, NOT Android APKs)

| Platform | Project | Why a separate build? | Current state |
| --- | --- | --- | --- |
| Samsung Q60A (Tizen TV) | `platforms/samsung-tizen` | Samsung Tizen web app must be packaged as signed WGT, not APK | Signed WGT UI preview built; PS streaming not wired |
| Roku TVs / streaming boxes | `platforms/roku` | Requires BrightScript/SceneGraph and Roku-supported media transport | Roku ZIP UI preview built; PS streaming not wired |
| iPhone / iPad | `platforms/apple` | iOS native arm64 UIKit, VideoToolbox and gamepad bridge instead of Android/MediaCodec | ARM64 UI-only IPA built (ad-hoc signed); PS streaming and exact UI parity missing |
| Apple TV HD A1625 and Apple TV 4K | `platforms/apple` | Separate tvOS target with TV controller focus and tvOS decoding | ARM64 UI-only tvOS IPA built (ad-hoc signed); PS streaming and exact UI parity missing |

**Apple TV clarification:** A1625 is Apple TV HD (2015), 1080p output, not Apple TV 4K. Target it alongside newer Apple TV 4K models with arm64 tvOS builds; model-specific validation required.

**Minimum Apple OS goals, not verified binary compatibility:** iOS 7 first shipped with Apple's 64-bit iPhone 5s, so it is the requested historical minimum experiment for arm64; tvOS 9 is the first tvOS release for the A1625. The latest Apple OS compatibility and signing must be established using current SDKs and real devices. The UI shell source includes experimental iOS 7/tvOS 9 deployment settings, but modern SDK/toolchain constraints may require raising them. These are not functional PlayStation clients or pixel-identical verified UI ports; building a Mach-O executable is not a hardware compatibility test.

**Windows IPA tool research** was cloned to `research/ios-build-tools/TheosWin` and `research/ios-build-tools/WindowsIPABuilder`. Both are third-party toolchains, not Apple signing services. WindowsIPABuilder describes ad-hoc fakesigned builds: this does NOT provide valid stock-iOS installation on all devices. The iOS 16.5 and tvOS 12.4 SDKs have been obtained and arm64 Mach-O UI shells compiled and packaged; native streaming/decoder port, legitimate stock-device signing/installation, and parity testing are outstanding. The existing Android UI/assets are the visual reference; the Apple UIKit shell is not yet pixel-perfect.

**Build commands on BEN-PC:** `powershell -File platforms/samsung-tizen/build-tizen.ps1 -CertificateProfile QuietHome` signs `platforms/samsung-tizen/Relay.wgt` using the existing Tizen Studio certificate profile; it stages only the five source assets (the Tizen `build-web` command encountered a missing Eclipse class here, but direct signing/packaging succeeded). `powershell -File platforms/roku/build-roku.ps1` creates `Relay-Roku-UI-preview.zip` for the Roku developer installer. `powershell -File platforms/apple/build-ios.ps1` creates `platforms/apple/dist/Relay.ipa`, and `powershell -File platforms/apple/build-tvos.ps1` creates `platforms/apple/dist/Relay-tvOS-UI-preview.ipa`. The Apple tools use LLVM, Apple SDKs and ad-hoc ldid signing. None of these non-Android builds currently support PS4/PS5 remote playback.

## Xbox Series S/X Developer Mode ? UWP build (November 23, 2026)

Added a standalone architecture-neutral Xbox Series S/X Developer Mode UWP build under `platforms/xbox-series/`. `build-xbox.ps1` generates a real Windows SDK APPX package, signed locally with the project's public development certificate; private key remains in the BEN-PC user certificate store. Uses existing Relay Android menu graphics, UI animation particle distribution, OGG-derived PCM cue audio, lossless wrapped menu loop, Xbox `Windows.Gaming.Input.Gamepad` navigation, and read-only PS5 PBS `/config.json` connectivity checks. It does NOT run PS5 live streaming and has not been installed on a physical Xbox. Windows SDK MakeAppx pack/unpack succeeded, four protocol tests passed and BEN-PC Edge render preview displayed the interface at 1920?1080. Self-signed certificate is not yet trusted by the destination console. Developer-mode package and public cert are also copied to `H:\Relay Xbox Series Dev Builds`. See `docs/RELAY_XBOX_SERIES_DEV.md` and `platforms/xbox-series/README.md` for build, safety, deploy, and remaining functionality.
