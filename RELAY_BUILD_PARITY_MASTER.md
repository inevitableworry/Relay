## What “same as Android” means

1. **Geometry:** same positioning/scaling of top-left tabs, main text, connect control, upper-right statuses, quick panel, dialogs and hints at equivalent aspect ratios and UI states. If a native display ratio differs, letterbox/scale intentionally rather than stretching.
2. **Materials:** layered dark background, blue-violet 3-D-looking orb, glowing points and moving cloud strata, shadow/halo, polished button surfaces—not plain rectangles, flat solid circles, or placeholder stars.
3. **Motion:** match Android orb growth, rotation speed, twinkle, particle layering, intro timings, button highlight and panel enter/exit animation. Compare frames at 0.5, 1, 3, 10 and 30 seconds after the same trigger.
4. **Audio:** copy the **original Relay menu cue assets** (open, close, confirm, focus, back, reveal) with proper attribution and implement playback on each platform. **Menu sound is not game stream audio.** Only mark streamed audio implemented when the PS5 decoded PCM/audio pipeline actually reaches the platform output.
5. **Input:** physical/virtual controllers and touchscreen (if supported) select equivalent UI targets. Switch Joy-Con/Pro and Vita hardware buttons/touch must be tested independently. Sending actual controller packets to a remote console is a separate verification gate.
6. **Translation:** Android Play Translate is canonical. Image OCR, video OCR, spoken Japanese ASR, English TTS, Natural Subtitle Replace and the muted-Japanese/English-dub test are distinct acceptance items; keep them synchronized across targets or mark explicit unsupported dependencies.
7. **No false passes:** screenshot likeness requires an actual reference-frame comparison, not simply reusing filenames/assets. An executable, NSP, VPK, APK or app package is only a build artifact.

## Change-to-release process (required on every request)

1. **Change registered:** write a dated entry in Change Log with exact user request and the Android feature/component touched.
2. **Android source of truth updated** (or documented as a shared design requirement when the request concerns only another platform).
3. **Port impact sweep:** enumerate every platform row; mark `implemented`, `needs work`, `unsupported—with reason`, or `not tested`. No silent skips.
4. **Regenerate/reuse upstream assets** rather than independently drawing a different logo/orb/button. Keep provenance and licensing in sync. A platform may convert files into its native format, but must preserve the design.
5. **Run check script** `python tools/check_relay_ui_parity.py`. This audits presence of source assets and rejects missing canonical source references. Also run `python platforms/switch1/verify_ui_parity.py`; a hash-lock change requires deliberate baseline review, not automatic rubber-stamping.
6. **Build relevant platforms**, retain compile/build stdout, record artifact path, hash and exact date. On multi-port requests build all unblocked ports, not only Android.
7. **Compare UI visually:** screenshot Android baseline + target at equivalent dimensions/state/frame; document 0.5, 1, 3, 10 and 30 second captures, material differences and any emulator artifacts. Run `python tools/compare_relay_ui_frames.py --android <android.png> --target <port.png> --out <comparison.png> --state home --time 3s`. It produces a side-by-side image and amplified pixel-difference heatmap; visually judge whether the same UI state/time was captured. An automated file/hash check or diff metric alone cannot establish visual parity.
8. **Play audio tests:** cue playback and game-stream audio must have separate checks. The sound asset existing in a package is not a playback pass.
9. **Hardware/device tests:** controllers, touch, decode, live session and model readiness; log success/failed/blocked and the reason.
10. **Update this file after EVERY change** in each affected row, unresolved-gap table and Change Log. If blocked, leave a concrete next action; never use words such as 'complete' or 'identical' without evidence.
